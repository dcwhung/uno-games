3. 一次 PLAY_CARD 嘅 Reducer ↔ Plugin 協作（R2 contract）

sequenceDiagram
  participant S as store.dispatch
  participant R as reducer.playCard
  participant P as plugin.onCardPlayed (classic)
  participant C as core helpers
  S->>R: PLAY_CARD{player, card, chosenColor?}
  R->>R: requireTurn · card in hand · drawnCard rule · plugin.isLegal
  R->>R: move card → discard, set activeColor (coloured card)
  R->>R: clear pendingDraw ⚠ AU-001 (before plugin)
  R->>R: UNO vulnerability check ⚠ AU-001 (before plugin)
  R->>P: onCardPlayed(state, player, card, chosenColor)
  P->>C: skipPlayer / drawCards / reverse (emit TurnSkipped …)
  P-->>R: { state, events } (phase may be choosing_color / challenge_window)
  alt phase !== playing
    R-->>S: return (no advance) — resumed later via finishPlay(player)
  else
    R->>R: finishPlay → hand empty? endRound : advanceTurn 1 step
    R-->>S: { state, events + TurnChanged }
  end

關鍵流程說明

點說明證據
唯一 mutation 入口store.dispatch → engine.apply；UI / bot 都唔直接改 stategameStore.ts:68-80
Skip 機制Plugin 設 currentPlayer 為被 skip 者 + emit TurnSkipped；reducer 再 advance 一步core.ts:119-124、reducer.ts:97-103
Opening card當 dealer 打出；WD4 重抽；Wild → dealer 左手邊揀色reducer.ts:182-222
Timing全部喺 botDriver.ts（bot delay、human UNO window、bot catch roll）botDriver.ts:13-16,62-83
Rejected action返回同一 state 物件 → 唔觸發 re-render → bot 錯誤 action 會 freeze（AU-003）reducer.ts:87-89

重要設計決定

  • Phase union 係 closed（7 個 literal）。Flex / Liar 要新增等待狀態就要改 types.ts + botDriver + HUD 三處 switch（AU-010）。
  • Opening card 視為 dealer 出牌，所以 opening effect 重用 plugin.onCardPlayed，唔使另寫 opening 邏輯。
  • UNO 判定同 pendingDraw 清除喺 plugin 之前 — Classic 冇問題，但 No Mercy discard-all / stacking 會撞（AU-001）。
